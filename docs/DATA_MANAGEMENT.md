# 数据管理与字典约定

## 数据获取与存储

1. 从所选研究的正式数据来源获取文件，记录 `source_manifest.template.csv` 中的 URL、日期、版本、周期、使用条件和 SHA-256。
2. 原文件放入 `data/raw/`，不覆盖原件；转换后放入 `interim/`，最终分析数据放入 `processed/`。
3. 逐周期填写 `variable_mapping.template.csv`；记录原变量、单位、缺失码、合并键和协调规则。
4. 检查每个组件的键唯一性、合并基数、匹配与未匹配人数，避免静默扩行或丢失。
5. 数据许可、访问控制与机构要求以实际来源为准。本模板不授予数据使用权。

## 可执行演示字典

`data_dictionary.csv` 的列名固定：

| 字段 | 含义 |
| --- | --- |
| `variable` | 标准化变量名，唯一且与输入列对应 |
| `dtype` | `string`、`category`、`integer`、`number` |
| `required` | `true` 或 `false`；表示是否允许单元格缺失 |
| `minimum` / `maximum` | 可选的闭区间数值边界 |
| `levels` | 类别集合，用 `|` 分隔 |
| `unit` | 单位；无单位使用 `none` |
| `description` | 变量含义 |
| `source` | 来源 |
| `missing_rule` | 缺失编码及处理说明 |
| `derivation` | 可审核的派生规则 |

演示中空单元格表示缺失，空白前后会被去除；`NA`、`999` 等不会被自动转换。
真实数据应先在协调层按来源文件明确重编码特殊缺失值。
数据字典模板中的 TODO 行仅用于填写，不能直接运行；演示校验器固定检查九个演示变量。

## 发布

`.gitignore` 排除了真实数据目录、本地配置、环境文件及生成报告。
提交前仍需检查暂存区与 notebook 输出。仅有合成标记或被 Git 忽略，并不能证明数据已经脱敏。
仅发布经授权的材料和经审核的汇总结果。不要向 issue、PR、日志或外部服务粘贴受限记录。
